# Project rules

- **The site is English-only.** Everything under `site/` — page text, UI strings, notices and error messages, `title`/`aria-label` attributes, code and CSS comments — must be in English. Do not add strings in other languages.
- **Effects List text is verbatim.** Effect and parameter descriptions in `site/effects-data.js` are copied exactly from the official ZOOM MS-60B+ Effects List; never translate or paraphrase them.
- Link the English ZOOM manual: `https://zoomcorp.com/manuals/ms-60bplus-en/#unique_41`. The header shows "Official Manual ENG/ITA" and also links the Italian one (`https://zoomcorp.com/manuals/ms-60bplus-it/`); every other link points to the English manual. Use `.` as the decimal separator and `en-GB` date formatting.
- The `.zptc` codec lives in `site/zptc.js` and is shared with `tools/zptc.mjs`. After changing it, run `node tools/zptc.mjs roundtrip patches/0* "patches/07Big Black .zptc"`: every file must round-trip byte for byte. Format notes: `docs/zptc-reverse-engineering.md`.
- Advice engine: `site/advice-engine.js` runs the rules; rules, placement tips and style profiles live in `site/advice-rules.js`. Every rule must cite at least one source (`ADVICE.addSources`) unless it is an objective fact about the pedal. Effect order is convention: order rules are `warning` or `tip`, never `error`. Check the source links now and then with `node tools/check-sources.mjs` (TalkBass blocks scripts and shows as "blocked"; open it in a browser). Rule packs (`site/rule-packs.js`) let users import their own rules as `.json`: keep them data-only and source-required. After changing rules, rule packs or starter chains run `node tools/advice-test.mjs` (starter chains must encode, stay under 100% DSP and raise no errors or warnings).
- Accounts (phase 1 of `docs/piano-login.md`): `deploy/accounts.mjs` (routes `/login`, `/register`, `/forgot`, `/reset`, `/verify`, `/logout`, `/api/me`), `auth.mjs` (PBKDF2, signed cookie `zms_session`, tokens, rate limits, CSRF), `db.mjs` (SQLite via `node:sqlite`, `DATA_DIR/studio.db`), `mail.mjs` (Gmail SMTP and Telegram like PatternMachine), `pages.mjs`. After changing any of them run `node tools/auth-test.mjs`. Account sync: `deploy/account-sync.mjs` (`POST /api/account/sync/<pedal>`, tables `patches` and `docs`) with the browser side `site/account.js` (syncs both pedals: `-library`, `-deleted` and the docs `-advice`, `-view`, `-builder`, `-rulepacks`, `-usb-backups`; merge rules `LIBMERGE.mergeDocs`); after changing them run `node tools/sync-test.mjs`. Secrets stay on the server, never in git: `mail.json` (`node set-mail.mjs`), `telegram.json` (`node set-telegram.mjs`), `.env` (`SITE_URL`, `SESSION_SECRET`, `MAIL_FILE`, `TELEGRAM_FILE`) in `/srv/apps/zoom-ms60b-app/`. Admins are created on the server with `node add-user.mjs --email … --admin`.
- Sync: `site/library-merge.js` (merge rules) is shared with `deploy/server.mjs`, which serves the site and the account sync API (the anonymous `/api/sync/<code>` was removed in 2026-10 and answers 410). After changing either, run `node tools/sync-test.mjs`. Account interface in `site/account.js` (loaded by every pedal page with `library-merge.js`): "Sign in" or the account menu in `.gh-header`, the signed-out notice on pages with `<body data-account-notice>`, `.account-local` labels shown only when signed out, the first-sign-in choice and sign-out (default: remove the data from this browser). After UI changes in the builder run `PW_CHANNEL=chrome node tools/e2e-test.mjs` (Playwright; `npm install` first). Sync data is backed up daily by `deploy/backup-sync-data.sh` (user crontab on the server, archives in `/srv/apps/zoom-ms60b-backups`). Server files go to `hp-ubuntu:/srv/apps/zoom-ms60b-app/` (`rsync -a deploy/*.mjs hp-ubuntu:/srv/apps/zoom-ms60b-app/`), sync data lives in `/srv/apps/zoom-ms60b-data` (outside the web root, never deploy over it).
- Pedal manager over USB (`site/pedal-manager.html`, experimental: lists the pedal memories next to My patches, reads, and writes with backup): `site/pedal-midi.js` speaks the SysEx protocol of zoom-zt2 (MIT, undocumented by ZOOM). After changing it run `node tools/midi-test.mjs` (simulated pedal in `tools/fake-pedal.mjs`). Never add a write command without a backup of the target memory and a read-back check.
- Tone ideas (`site/tones.html`, `site/tones.js`, data in `site/tone-ideas.js`): every bassist fact cites a source key from `advice-rules.js`; styles come from the advice styles with a starter. Share links (builder and Tone ideas) use `site/patch-link.js`.
- Deploy: run `node tools/stamp-update.mjs` first ("Last update" under the GitHub link in every footer), commit, then `rsync -a --exclude '.DS_Store' site/ hp-ubuntu:/srv/apps/zoom-ms60b/` (served at https://zoom.tongatron.org). Bump the `?v=` query strings in the HTML when CSS/JS change.
- Second pedal: **Zoom MS-50G+ (guitar), "not tested"** in `site/ms-50g/` (own `pedal.js`, `effects-data.js`, `firmware-data.js`, `advice-rules.js`, effect images; shared scripts and CSS from `site/`). `site/pedal.js` holds the MS-60B+ settings; shared scripts read `PEDAL` for URLs and the storage/sync prefix. MS-50G+ data comes from `python3 tools/extract-effects-list.py documentazione/ms-50gplus/E_MS-50Gplus_EffectsList.pdf` (verbatim, checked word for word against the PDF) and zoom-zt2 `ms-50gp/effects_sort.txt`; the 24 ★ Handy Guitar Lab add-ons have no firmware entry (`null`) and stay out of the builder. Its advice is objective checks only: add guitar rules with guitar sources, never reuse the bass ones. Page text in `site/ms-50g/*.html` mirrors the MS-60B+ pages: carry layout changes over by hand.
