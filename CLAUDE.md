# Project rules

- **The site is English-only.** Everything under `site/` — page text, UI strings, notices and error messages, `title`/`aria-label` attributes, code and CSS comments — must be in English. Do not add strings in other languages.
- **Effects List text is verbatim.** Effect and parameter descriptions in `site/effects-data.js` are copied exactly from the official ZOOM MS-60B+ Effects List; never translate or paraphrase them.
- Link the English ZOOM manual: `https://zoomcorp.com/manuals/ms-60bplus-en/#unique_41`. The header shows "Official Manual ENG/ITA" and also links the Italian one (`https://zoomcorp.com/manuals/ms-60bplus-it/`); every other link points to the English manual. Use `.` as the decimal separator and `en-GB` date formatting.
- The `.zptc` codec lives in `site/zptc.js` and is shared with `tools/zptc.mjs`. After changing it, run `node tools/zptc.mjs roundtrip patches/0* "patches/07Big Black .zptc"`: every file must round-trip byte for byte. Format notes: `docs/zptc-reverse-engineering.md`.
- Advice engine: `site/advice-engine.js` runs the rules; rules, placement tips and style profiles live in `site/advice-rules.js`. Every rule must cite at least one source (`ADVICE.addSources`) unless it is an objective fact about the pedal. Effect order is convention: order rules are `warning` or `tip`, never `error`. Check the source links now and then with `node tools/check-sources.mjs` (TalkBass blocks scripts and shows as "blocked"; open it in a browser). Rule packs (`site/rule-packs.js`) let users import their own rules as `.json`: keep them data-only and source-required. After changing rules, rule packs or starter chains run `node tools/advice-test.mjs` (starter chains must encode, stay under 100% DSP and raise no errors or warnings in their own style).
- Sync: `site/library-merge.js` (merge rules) is shared with `deploy/server.mjs`, which serves the site and the `/api/sync` API. After changing either, run `node tools/sync-test.mjs`. After UI changes in the builder run `PW_CHANNEL=chrome node tools/e2e-test.mjs` (Playwright; `npm install` first). Sync data is backed up daily by `deploy/backup-sync-data.sh` (user crontab on the server, archives in `/srv/apps/zoom-ms60b-backups`). Server files go to `hp-ubuntu:/srv/apps/zoom-ms60b-app/` (`rsync -a deploy/server.mjs hp-ubuntu:/srv/apps/zoom-ms60b-app/`), sync data lives in `/srv/apps/zoom-ms60b-data` (outside the web root, never deploy over it).
- Deploy: `rsync -a --exclude '.DS_Store' site/ hp-ubuntu:/srv/apps/zoom-ms60b/` (served at https://zoom.tongatron.org). Bump the `?v=` query strings in the HTML when CSS/JS change.
