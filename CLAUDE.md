# Project rules

- **No native browser dialogs.** The pages never call `alert`, `confirm` or `prompt`: questions and messages come from `site/dialogs.js` (`DIALOGS.confirm`, `DIALOGS.alert`, `DIALOGS.toast`, in the style of the site's Overlay dialogs; loaded before `builder.js` and `pedal-manager.js`), from the Pedal manager's own `#usb-confirm` dialog, or from the dialogs of `account.js` and `report.js`. `tools/e2e-test.mjs` and `tools/pedal-manager-test.mjs` fail when the browser raises one. The design prototypes in `site/designs/` use `PROTO.notice`.
- **The site is English-only.** Everything under `site/` — page text, UI strings, notices and error messages, `title`/`aria-label` attributes, code and CSS comments — must be in English. Do not add strings in other languages.
- **No mobile version, by decision (2026-10-27).** The site is for windows of at least 800 × 640 px (computers, tablets held sideways). Do not add phone or small-screen layouts, scrolling fallbacks or media queries for them. Below that size `fullscreen.js` shows a notice (`.fs-small`, `fullscreen.css`) instead of the page: it says the window is too small and how big it is, suggests a bigger screen or the browser's full-screen mode, and says what the site does; keep that description true when pages or features change. The limit is one number in three places (the media query in `fullscreen.css`, the text in `fullscreen.js`, `tools/fullscreen-test.mjs`): change them together, and only after checking that every page fits at the new size. The home page is `site/index.html` (served at `/`; it scrolls and is not part of this layout; its images are in `site/landing/`, whose `index.html` is only a small page that sends the old `/landing/` address to `/`; old root links with a query or #fragment go on to `/ms-60b/`); its "Help wanted" box has no steps, only a **Help us test the MS-50G+** button to `ms-50g/help.html`, and its header has a **Contact us** button that opens the form of `site/report.js` (contact mode, same Telegram bot; `report.js` also works on pages without a status bar).
- **Effects List text is verbatim.** Effect and parameter descriptions in `site/ms-60b/effects-data.js` are copied exactly from the official ZOOM MS-60B+ Effects List; never translate or paraphrase them.
- Link the English ZOOM manual: `https://zoomcorp.com/manuals/ms-60bplus-en/#unique_41`. The Resources page, linked from the Guide (`site/ms-60b/resources.html`, `site/ms-50g/resources.html`) lists the manuals in English and Italian and the Effects List PDF; it also links the Italian one (`https://zoomcorp.com/manuals/ms-60bplus-it/`); every other link points to the English manual. Use `.` as the decimal separator and `en-GB` date formatting.
- The `.zptc` codec lives in `site/zptc.js` and is shared with `tools/zptc.mjs`. After changing it, run `node tools/zptc.mjs roundtrip patches/0* "patches/07Big Black .zptc"`: every file must round-trip byte for byte. Format notes: `docs/zptc-reverse-engineering.md`.
- Advice engine: `site/advice-engine.js` runs the rules; rules, placement tips and style profiles live in `site/ms-60b/advice-rules.js`. Every rule must cite at least one source (`ADVICE.addSources`) unless it is an objective fact about the pedal. Effect order is convention: order rules are `warning` or `tip`, never `error`. Check the source links now and then with `node tools/check-sources.mjs` (TalkBass blocks scripts and shows as "blocked"; open it in a browser). Rule packs (`site/rule-packs.js`) let users import their own rules as `.json`: keep them data-only and source-required. After changing rules, rule packs or starter chains run `node tools/advice-test.mjs` (starter chains must encode, stay under 100% DSP and raise no errors or warnings).
- Accounts (phase 1 of `docs/piano-login.md`): `deploy/accounts.mjs` (routes `/login`, `/register`, `/forgot`, `/reset`, `/verify`, `/logout`, `/api/me`, `/api/report`), `auth.mjs` (PBKDF2, signed cookie `zms_session`, tokens, rate limits, CSRF), `db.mjs` (SQLite via `node:sqlite`, `DATA_DIR/studio.db`), `mail.mjs` (Gmail SMTP and Telegram like PatternMachine), `pages.mjs` (every server page is wrapped in `<!--email_off-->`: Cloudflare would turn the emails into "[email protected]" and the page's CSP blocks the script that decodes them). After changing any of them run `node tools/auth-test.mjs`. Account sync: `deploy/account-sync.mjs` (`POST /api/account/sync/<pedal>`, tables `patches` and `docs`) with the browser side `site/account.js` (syncs both pedals: `-library`, `-deleted` and the docs `-advice`, `-view`, `-builder`, `-rulepacks`, `-usb-backups`; merge rules `LIBMERGE.mergeDocs`); after changing them run `node tools/sync-test.mjs`. Secrets stay on the server, never in git: `mail.json` (`node set-mail.mjs`), `telegram.json` (`node set-telegram.mjs`), `.env` (`SITE_URL`, `SESSION_SECRET`, `MAIL_FILE`, `TELEGRAM_FILE`) in `/srv/apps/zoom-ms60b-app/`. Admins are created on the server with `node add-user.mjs --email … --admin`; they get the user console `/admin` (`deploy/admin-pages.mjs`, routes in `accounts.mjs`: search and sort accounts, reset link, sign out everywhere, make/remove admin, download data, delete with confirmation, read-only patch list; every action goes to `admin_log`; an admin never acts on their own account).
- SEO: titles, descriptions, canonical, Open Graph, Twitter tags, the structured data of the home page, `site/sitemap.xml` and `site/robots.txt` are written by `node tools/seo-tags.mjs` from one table (keywords: the pedal names MS-60B+ and MS-50G+, effects list, patch editor, .zptc, Handy Guitar Lab): change a title or description there, run it and commit the result; a new public page goes in the table. Account and server pages carry `noindex` (`deploy/pages.mjs`) and are disallowed in `robots.txt`. `tools/fullscreen-test.mjs` checks it.
- Report a problem: `site/report.js` (loaded by every page with a status bar; it adds the **Report a problem** button after Privacy and a dialog with name, email and message; any element with `data-report="report"` or `"contact"` opens it, see Contact us below) posts to `POST /api/report` in `deploy/accounts.mjs`: open to everyone, 5 per address per 15 minutes, 3000 characters, the page, pedal, last-update time, window size and browser go with it while the ticked box "Send technical details" stays ticked (the account email of a signed-in visitor is always added by the server). The message goes to the site's own Telegram bot (`telegram.json`, made with `node set-telegram.mjs`; the same bot gets the sign-up notices; it is not PatternMachine's) and nothing is stored on the server; without Telegram the route answers 503 and the dialog sends people to GitHub issues. `node tools/auth-test.mjs` and `PW_CHANNEL=chrome node tools/fullscreen-test.mjs` cover it. `site/privacy.html` and the Troubleshooting of both Guides describe it: keep them true.
- Sync: `site/library-merge.js` (merge rules) is shared with `deploy/server.mjs`, which serves the site and the account sync API (the anonymous `/api/sync/<code>` was removed in 2026-10 and answers 410). After changing either, run `node tools/sync-test.mjs`. Account interface in `site/account.js` (loaded by every pedal page with `library-merge.js`): "Sign in" or the account menu in `.gh-header`, the signed-out notice on pages with `<body data-account-notice>`, the sign-up reminder dialog on pages with `<body data-account-welcome>` (Effects, Patch builder, Tone ideas, Pedal manager, both pedals; shown once the server confirms the visitor is signed out; "Ignore this message" sets localStorage `account-welcome` = `ignored`, any other way of closing sets sessionStorage `account-welcome` = `later`, so it comes back at the next visit; the tests that load pages signed out set the `ignored` flag in an init script because the dialog covers the page), `.account-local` labels shown only when signed out, the first-sign-in choice and sign-out (default: remove the data from this browser). After UI changes in the builder run `PW_CHANNEL=chrome node tools/e2e-test.mjs` (Playwright; `npm install` first). The accounts database is backed up daily by `deploy/backup-data.sh` (`db-backup.mjs`, `VACUUM INTO`; user crontab on the server, archives in `/srv/apps/zoom-ms60b-backups`, 30 days). `site/privacy.html` describes what is stored: update it when the stored data, the emails or the backups change. Server files go to `/srv/apps/zoom-ms60b-app/` on the server (`rsync -a deploy/*.mjs deploy/backup-data.sh giovanni@100.81.62.48:/srv/apps/zoom-ms60b-app/`, then `ssh -t giovanni@100.81.62.48 'sudo systemctl restart zoom-ms60b.service'`, which needs the user's password), the database `studio.db` lives in `/srv/apps/zoom-ms60b-data` (outside the web root, never deploy over it).
- Pedal manager over USB (`site/ms-60b/pedal-manager.html`: lists the pedal memories next to My patches, reads, and writes with backup): `site/pedal-midi.js` speaks the SysEx protocol of zoom-zt2 (MIT, undocumented by ZOOM). After changing it run `node tools/midi-test.mjs` (simulated pedal in `tools/fake-pedal.mjs`). Never add a write command without a backup of the target memory and a read-back check. A patch with 6 effects goes to the pedal without the BLANK slot (`ZPTC.forPedal`, called by `sendNow`): the pedal holds 6 entries, accepts a 7-entry patch and reads it back unchanged, then drops its last effect (found 2026-10-28; the read-back cannot catch it, `tools/midi-test.mjs` covers it). Not connected, the "On the pedal" list shows the memories as last read (`ms60b-usb-last-read`, the whole PTCF of each) and a readable one opens to its effects, with Copy to My patches and Download only. **Clear patch** (selected memory, also one the page cannot decode: its raw bytes are backed up first) proposes the name `Empty` in the confirmation; `PW_CHANNEL=chrome node tools/pedal-manager-test.mjs` covers it. Backups has **Delete all** (asks first): a deleted backup stays in `ms60b-usb-backups` as `{ id, deleted: true, at }` for 90 days, because `LIBMERGE.mergeBackups` only ever adds the backups of two copies and an account would bring them back (`node tools/sync-test.mjs` covers it). **My patches** has a trash button on each saved patch (asks first; it keeps the deletion in `ms60b-deleted` like the builder's `writeLibrary`, so an account deletes it elsewhere). **Undo** (button under the connection box, Ctrl/⌘+Z) takes back, newest first and only while the page stays open, a deleted or copied patch and every write to the pedal (write, rename, clear, a new order, a restored backup); a change to the pedal is undone like any write: read the memory, back it up in Backups, ask, write, read back (`undoWrites`); while a new order is planned it undoes one move at a time. A memory the page cannot decode has no Undo (its backup stays in Backups); deleting backups has none either. `PW_CHANNEL=chrome node tools/pedal-manager-test.mjs` covers it. The MIDI log has a full-screen button (Fullscreen API, or the whole window when the browser has none). Backups and the MIDI log start closed (click the title). The connection box shows the real MS-60B+ of the landing page (`site/landing/pedal-ms60b-small.webp`, a small copy of `pedal-ms60b.webp`) at the left of the steps: grey and dim until the pedal is connected, in colour once it is (`is-connected` on `.usb-connect`, set by `setConnected`).
- Interface (Panels layout, both pedals): every page is laid out so the page never scrolls and long lists scroll inside their pane (`site/fullscreen.css`, `site/fullscreen.js`: pedal menu, contents list of the documents with the entry of the section being read highlighted, small-screen notice). **Addresses:** the pages of each pedal live in the folder of that pedal, so every address after the domain says which pedal it is for: `https://zoommultistompstudio.tongatron.org/ms-60b/…` and `/ms-50g/…`. `site/ms-60b/` holds the MS-60B+ pages and its own `pedal.js`, `effects-data.js`, `firmware-data.js`, `advice-rules.js`, `technical-notes.md` and `assets/effects/` (as `site/ms-50g/` does for the guitar); the shared scripts and CSS stay in `site/`, and the pages reach them with `../`. `privacy.html` (shared) and `landing/` are at the root. The old root addresses of the MS-60B+ (`/`, `/index.html`, `/builder.html`, `/tones.html`, `/pedal-manager.html`, `/resources.html`, `/technical-notes.html`, `/guide.html`, `/usb.html`) are small pages (`site/index.html`, `site/builder.html`, …) that send the browser to `/ms-60b/…`, keeping the query string and the #fragment, so old patch links still open. They are **not server redirects** on purpose (found on 2026-10-29): the service worker of a returning visitor stores a page but not a redirect, and with redirects it kept showing the old cached page for ever; do not turn them into redirects, and do not put them or `./` in the core list of `sw.js`. Only `/technical-notes.md` redirects (`MOVED` in `deploy/server.mjs`), for an old cached page that still asks for it. Pages (in `site/ms-60b/`): `index.html` (Effects), `builder.html`, `tones.html`, `pedal-manager.html`, `resources.html`, `technical-notes.html`, `guide.html`, plus `site/privacy.html` (its text is in the page), and the same for the MS-50G+ in `site/ms-50g/` (`index`, `builder`, `resources`, `guide`, `help`; no Pedal manager or Tone ideas, a "Not tested" bar under the header with the **Help us** button at its right end, which opens `help`). Page text of the two pedals mirrors each other: carry text changes over by hand. `guide.html` is the how-to (the Guide button is top right, before the account menu): keep it true to what the pages do; the how-to for loading a patch on the pedal lives only there, and the Resources page is linked from it, not from the status bar. The Effects detail is a pane next to the list (`app.js`: no previous/next buttons, "Add to patch" under the description). Advice has no on/off switch. The Patch builder has three columns: My patches at the left, the chain, and the patch with Advice under it. The status bar has the tongatron.org button (B3 of tongatron.org/pulsanti) all the way to the left, then Source on GitHub, Privacy and Report a problem, and the update time at the right; the ZOOM data note (© 2024 ZOOM CORPORATION, manufacturer names) is in the "Data and credits" section of each Guide, not in the bar. The header of every MS-60B+ page has the green tag "Tested on firmware 1.20" just left of the Guide button (`.fs-fw`, in each page's HTML: change it when the tested firmware changes; the same full text at every width, down to 800 px); the pedal menu lists "MS-60B+ bass" plain and "MS-50G+ guitar" with "Not tested". In the Patch builder's Advice pane "Plug into" sits above the Errors / Warnings / Tips row. `site/_fullscreen/` only holds redirects from the old test addresses. After layout changes run `PW_CHANNEL=chrome node tools/fullscreen-test.mjs` (both pedals, all pages and sizes). Plan and to-dos: `docs/piano-fullscreen.md`.
- Tone ideas (`site/ms-60b/tones.html`, `site/tones.js`, data in `site/tone-ideas.js`): every bassist fact cites a source key from `advice-rules.js`; styles come from the advice styles with a starter. Links that open a patch in the builder (Tone ideas, Pedal manager) use `site/patch-link.js`; the builder has no Share link button (removed 2026-10-28), but links made earlier must keep opening.
- Deploy: run `node tools/stamp-update.mjs` first ("Last update" under the GitHub link in every footer), commit, then `rsync -a --exclude '.DS_Store' site/ giovanni@100.81.62.48:/srv/apps/zoom-ms60b/` (served at https://zoommultistompstudio.tongatron.org). Deploy over Tailscale: `100.81.62.48` is the node `hp-ubuntu`; the `hp-ubuntu` SSH alias points to `giovanni-pc-ubuntu.local`, which only works on the home LAN (from Claude Code the SSH connection needs the sandbox off). Bump the `?v=` query strings in the HTML when CSS/JS change; if a deploy is interrupted, bump them again before redeploying, because Cloudflare may have cached the old file under the new URL.
- Address (moved 2026-10-28): the site is `https://zoommultistompstudio.tongatron.org` (`SITE_URL`, default in `deploy/site-url.mjs`); `zoom.tongatron.org` (`LEGACY_ORIGINS`) only redirects. `deploy/legacy-host.mjs` answers the old Host: a page request gets a hand-over page that copies what the browser keeps for the old address (patches, backups, settings; localStorage belongs to one address) to `/moved` of the new one and then goes to the same page there; `/sw.js` is a worker that removes itself and the caches; any other GET/HEAD is a 301; POST is 410. Sign-in cookies do not move: accounts sign in again. The Cloudflare tunnel must keep both public hostnames pointing at port 8097 and pass the Host header (the default). After changing any of it run `PW_CHANNEL=chrome node tools/legacy-test.mjs`.
