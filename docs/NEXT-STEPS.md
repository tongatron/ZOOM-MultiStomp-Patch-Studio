## 0. Zoom MS-50G+ (guitar) — not tested

`site/ms-50g/` reuses the MS-60B+ codec, builder and catalog with the MS-50G+ Effects List (127 effects) and the zoom-zt2 firmware table (103 IDs). Nothing has been checked on a real MS-50G+. A tester with the pedal should:

1. Export one simple patch from Handy Guitar Lab for MS-50G+ (e.g. COMPRESSOR with known values) and send the `.zptc`: `ZPTC_PEDAL=ms-50g node tools/zptc.mjs decode file.zptc` shows whether header, PRM2 and the bit layout match the MS-60B+.
2. Import a patch generated by the builder (COMPRESSOR + an amp such as MS1959 DRIVE + DELAY) and report the values shown in the app and on the pedal.
3. Note the "Processor %" of a few patches to calibrate `DSP_SCALE` (now borrowed from the MS-60B+).
4. Amp models (PREAMP category): check whether PRM2 byte 20 needs the per-slot amp bits like the MS-60B+ amps (not set now), and whether hidden parameters appear in exports.
5. The 24 Handy Guitar Lab add-ons (★) need their effect IDs: export a patch that uses one of them.
6. Undecoded ranges (raw values in the builder): LOW-PASS FILTER SENSE / RESO, ENVELOPE GENERATOR FILTER TYPE, PARAMETRIC EQ FREQ / Q, MATCH30 DRIVE VOL, DUAL DELAY DEPTH, SLAP BACK DELAY TIME.
7. Guitar advice: only objective checks exist. Order, style and tone rules need guitar sources.

**Testers who are far away.** The **Help us** button of the "Not tested yet" bar (every MS-50G+ page) opens `site/ms-50g/help.html`: steps 1–6 above written for someone who has only the pedal and the Handy Guitar Lab app (iPhone/iPad), with the time each test takes (setup and tests 1–3 about 50 minutes, everything about 4 hours) and what we would need back. It is written as what would help, not as instructions: **Contact us**, right after the description, opens a form (the Telegram bot of the site; an email address is required) that asks how much time the person can give, so that the tests are organised together; the files come by email, as a reply. Patches in tests 4–6 are named after the value the app shows, so the file name and the raw values (`ZPTC_PEDAL=ms-50g node tools/zptc.mjs decode file.zptc`) can be put side by side. `tools/fullscreen-test.mjs` checks that the two test patches of the page (TEST A, TEST C) open in the builder with the effects and the DSP load the page quotes.

What the MS-60B+ tests taught and the page already uses ([`controlli-pedale.md`](controlli-pedale.md)):
- PARAMETRIC EQ has the same ranges on both pedals. On the MS-60B+ Q is 0.5 + raw × 0.1 (raw 0, 1, 2, 27 = 0.5, 0.6, 0.7, 3.2) and FREQ is not linear (raw 4 = 50 Hz, raw 16 = 300 Hz): test 4 asks for six (FREQ, Q) pairs, enough to confirm it. Not decoded in the codec yet on either pedal, so the MS-50G+ stays "raw".
- The MS-60B+ holds six entries: a six-effect file written with the BLANK slot first (seven entries) lost its sixth effect on the pedal over USB. Test 3 asks whether the MS-50G+ keeps all six when the patch comes through the app; if not, write six-effect files without BLANK for the MS-50G+ too (`ZPTC.forPedal`).
- With the editor mode on, the pedal rewrites a memory by itself when its slots are browsed, and saves what is touched: testers are told to use free memories, make a backup first and leave the knobs alone while the app is connected.
- A value read on the display is only useful with its raw value next to it, and a frequency scale needs five or more points: the tests ask for the lowest, the highest and some in between.

## 1. Finish decoding the `.zptc` parameters

The builder can already write every parameter, but some formats are only known as raw stored values.
Method (see `docs/zptc-reverse-engineering.md`): export the same patch from Handy Guitar Lab two or three times, changing **only one parameter**, note the displayed values, then run `node tools/zptc.mjs decode file.zptc` to read the raw values and add the rule to `codec()` in `site/zptc.js`.

**Raw — format unknown (24 parameters):**

| Range | Parameters |
|---|---|
| `32 Hz – 6.3 kHz` | AMPG SVT, SMR400, B-MAN100, AC 370 — MID-FREQ |
| Continuous frequencies (`20 Hz – 20 kHz`, `20 Hz – 640 Hz`, `500 Hz – 20 kHz`, `80 Hz – 2.5 kHz`, `300 Hz – 1.5 kHz`, `100 Hz – 1.0 kHz`, `350 Hz – 3.2 kHz`, `40 Hz – 600 Hz`, `1.5 kHz – 22.0 kHz`) | BASS PARAMETRIC EQ FREQ, LOW EQ FREQ, HIGH EQ FREQ, SPLITTER FREQ, DUAL COMPRESSOR FREQ, CLEAR DRIVER PREAMP MID-FREQ, 1073 PREAMP MID-F, SOLID PREAMP LO-FREQ / HI-FREQ |
| `OFF, 60 Hz – 800 Hz`, `OFF, 20 Hz – 120 Hz` | BASS STEREO CHORUS / BASS VINTAGE FLANGER LOCUT, DJENT PREAMP LOCUT |
| `0.5 – 16.0`, `1.0 – 10.0` | BASS PARAMETRIC EQ Q, 160 COMPRESSOR RATIO |
| `-10 – -1, 1 – 10` | SENSE on BASS AUTO WAH, Z TRON FILTER, BASS CRY FILTER |
| Others | BASS MONO PITCH SHIFTER SHIFT (`-12 – 12, 24`), DUAL DELAY DEPTH (`MN-0 – ST-50`), ENVELOPE GENERATOR FILTER TYPE (`HPF2 – LPF4`) |

Suggested exports: one parameter at its minimum, at its maximum and at one middle value is usually enough to find offset and step.

**Inferred — "unverified" in the builder (18 parameters):**

- `-15.0 – 15.0` and `-10.0 – 10.0` (SMR400, TE400SMX, EBH360 tone stacks): assumed 0.5 dB steps like the verified ±12 / ±20 ranges.
- `OFF, 1 – 6` (DI-5 PREAMP TONE) and `OFF – 100` (SUN CB DIST): assumed OFF = 0.
- Delay MODE (`SHORT, LONG, ♩`, `TIME, ♩`): SHORT/LONG are indexes; the tempo-synced note values after `♩` are not decoded.

Close each one with a generated patch checked on the pedal, then add the range to `VERIFIED_DECIMAL` or mark the codec as verified.

## 4. Advice engine

- **Output choice** is done: "Plugging into" (bass amp or mixer/PA/headphones) switches the CABINET advice to exact warnings with a one-click fix. It is remembered with each saved patch in My patches (and in Backup files) but not stored in the `.zptc` file, which has no field for it. Possible next step: more output-dependent rules (levels, EQ) once a source is found.
- **Style profiles** were removed from the builder (style picker, style card, starter chain button, style fit). Styles and starters remain as data for Tone ideas.
- **Test the starter chains on the pedal** (6 styles with a starter) and adjust their values by ear.
- **More rules**, each with a source: stereo output, patch level, tuner and mute usage (no source found yet for the MS-60B+). Done: level stacking, delay repeats and mix, long reverb tails, deep-low EQ boosts, high compression ratios, very hard compression, synth with no clean bass, noise reduction threshold. (Footswitch effects and tempo-synced delays are done.)
- **Rule packs (v3)**: done. Import and export `.json` packs from the Advice panel ("Rule packs"); the format is documented at the top of `site/rule-packs.js`. Packs are data only (effect or role, parameter conditions, before/after, first/last, each/once/absent), always need a source and can be `tip` or `warning`. Rules can carry a one-click fix (`move-before`, `move-after`, `set`). Packs can also be created and edited in the page with a form ("New rule pack" and "Edit"; `site/rule-pack-editor.js`).
- **Source health**: `node tools/check-sources.mjs` checks every source. On 2026-10-25: 26 links, none broken; 3 TalkBass threads cannot be verified from automation (Cloudflare blocks scripts and the test browser), the rest answer; redirected URLs were updated.

## 4b. Pedal over USB (Web MIDI) — experimental

`site/pedal-manager.html` (not linked from the menus yet) reads and writes patches straight from the pedal in Chrome or Edge: identity request, editor mode, patch memory size, current patch and patch memories, decoded with `site/zptc.js`, with "Open in builder" and ".zptc" download. The SysEx commands, 7-bit packing and CRC32 come from `zoomzt2.py` in zoom-zt2 (MIT) and are not documented by ZOOM; `site/pedal-midi.js` implements them, `node tools/midi-test.mjs` tests them against a simulated pedal (`tools/fake-pedal.mjs`). Tried on a real MS-60B+ (firmware 1.20, macOS, Chrome) on 2026-10-26: the port is "ZOOM MS Plus Series"; the identity reply is `7e 00 06 02 52 6e 00 27 00 "1.20"` (model byte `0x6e` like zoom-zt2, model code `0x27`); 100 memories of 848 bytes, 10 per bank; the current patch (`64 13` → `64 12 01 <length 848> …`) arrived with a valid CRC and decoded to the patch on the pedal (280-byte PTCF, 4 effects).

1. **Test reading on the pedal**: current patch done; memory 10 arrives with a valid CRC and the right name (factory "D.I Plus Preamp", stored without the BLANK slot, now decoded). Still to check: the effects and values of a few memories against the pedal, and memories across a bank change (10 → 11).
2. **Writing** (built, not yet tried on the pedal): section 3 of `pedal-manager.html` writes the patch open in the builder or a `.zptc` file to a memory (`45 00 00 bank slot length …`, padded to the memory size, CRC32). Before writing it reads the target memory and keeps it as a backup (localStorage `<pedal>-usb-backups`, last 30, plus a downloaded `.zptc`), asks for confirmation with both names, then reads the memory back and compares the PTCF bytes. Backups can be restored from the page. Next: try it on a memory that is not needed, check the patch on the pedal, then restore.

3. **Pedal manager** (built on the same page, not yet tried on the pedal): after connecting, all memories are read (number, name, effects, DSP). Selecting a memory shows its chain with Open in builder, Copy to My patches, Download and Read again; every patch in My patches (and the builder's open patch, or a `.zptc` file) has "Send to memory N" for the selected memory, through the same backup → confirm → write → read-back flow. Rename re-encodes the patch from its raw values (only if it round-trips byte for byte) with the new name. Edit: "Edit in builder" opens the memory in the builder (`#p=…&m=N`, `<pedal>-pedal-edit` in localStorage); a bar there sends it back (`pedal-manager.html#send=N`), keeping the description, header, slot layout and PRM2 patch data of the original (`_prm2Refresh` recomputes only the amp bits and the selected slot). Clear patch writes an empty patch named "Empty" (only the BLANK slot, `ZPTC.encode({ empty: true, effects: [] })`) through the same flow; not yet tried on the pedal, so check that it accepts a patch with no effects. Next: try all of this on the pedal and time the full read (100 memories).

## 5. Patch builder

- Undo/redo is done (history of the editor in memory, Ctrl/⌘+Z, Shift+Ctrl/⌘+Z; slider and name edits collapse into one step). Possible extension: keep the history across page reloads.

- Sync "My patches" across devices: done (Sync button in My patches; a random code identifies the shared copy, `deploy/server.mjs` merges it, newest edit wins and deletions travel too). Possible extension: a list of the devices that sync.
- PWA: done (`manifest.webmanifest`, `sw.js`). Pages are stale-while-revalidate, while `?v=` scripts and stylesheets are cached per version, so a page never mixes its own version with older scripts. After a deploy the visitor sees a "new version available" bar (always bump the `?v=` in the HTML). PNG icons are in place.
